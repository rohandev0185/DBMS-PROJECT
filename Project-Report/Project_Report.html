01 Abstract

This project presents the design, development, and implementation of a Library Circulation and Digital Resource Management System using MySQL 9.7 as the relational database engine and Python Flask as the web application backend. The system models a real-world university library through a normalized 13-table relational schema in Third Normal Form (3NF), managing the full lifecycle of physical book copies — from cataloguing and member registration to circulation (issue and return), fine calculation, and reservation queuing — while simultaneously indexing digital e-books and journals.

A browser-based user interface, built with Vanilla HTML, CSS, and JavaScript, connects to the MySQL database via a REST API and supports live insertion, deletion, and viewing of records. The project demonstrates practical application of relational modelling concepts including entity identification, foreign-key referencing, many-to-many junction tables, and multi-table analytical queries.

02 Introduction & Problem Statement

Background

University libraries are complex operational environments that maintain thousands of physical books, track borrowing by hundreds of members, impose return deadlines, collect fines for overdue items, and host growing collections of electronic resources. Managing this with paper registers or spreadsheets leads to data inconsistency, duplication, and slow lookups.

A relational database provides the ideal solution: structured tables with referential integrity ensure no book copy can be issued to a non-existent member, no fine can reference a non-existent issue, and aggregation queries can instantly answer complex operational questions.

Problem Statement

The system must solve the following real-world problems faced by a university library:

  • Book catalogue management: Maintaining book titles, ISBNs, authors, categories, and publishers without redundancy.
  • Physical copy tracking: Each physical copy has a unique accession number and availability status (Available / Issued / Reserved / Lost).
  • Circulation control: Recording issue and return dates per copy per member, preventing double-issuing.
  • Overdue and fine management: Identifying overdue books and associating fine amounts with issue records.
  • Reservation queuing: Allowing members to reserve popular titles and tracking queue positions.
  • Digital resource access logging: Tracking who accessed which e-book or journal and when.
  • Role-based portal access: Separate workflows for Admin (insert, delete, manage) and Student (browse, borrow).

03 Objectives & Scope

Objectives

  1. Design a normalized relational schema (3NF) that eliminates data redundancy and maintains referential integrity for all library entities.
  2. Implement the full DDL (table creation, constraints, views) and DML (seed data, transactions) in MySQL 9.7.
  3. Build a Flask REST API that exposes CRUD endpoints for all major entities.
  4. Develop a browser-based UI supporting live Insert, Delete, and View operations with real-time MySQL synchronization.
  5. Execute and present five analytical SQL queries covering availability tracking, circulation history, overdue reporting, demand analysis, and fine summaries.
  6. Demonstrate the system live during Presentation-III.

Scope

In Scope: Book catalogue, physical copy management, member registration, issue/return workflow, fine records, reservation queue, digital resources, digital access log, role-based UI, 5 evaluated SQL queries, REST API with JSON responses.
Out of Scope: Payment gateway integration, email/SMS notifications, mobile application, barcode/RFID hardware, multi-branch library support.

06 Relational Schema & Normalization

Relational Schema

RESERVATION  (ReservationID PK, MemberID FK->MEMBER, BookID FK->BOOK,
              ReservationDate DATE, QueueNo INT, Status VARCHAR)

              Amount DECIMAL(8,2), PaidStatus ENUM[Paid,Unpaid])
DIGITAL_RESOURCE   (ResourceID PK, Title, Format, AccessURL)
DIGITAL_ACCESS_LOG (LogID PK, MemberID FK->MEMBER,
                    ResourceID FK->DIGITAL_RESOURCE, AccessDate DATETIME)

Normalization Analysis

First Normal Form (1NF)

All attributes are atomic. No repeating groups. The M:N relationship between BOOK and AUTHOR is resolved into the BOOK_AUTHOR junction table instead of storing a comma-delimited author column.

Second Normal Form (2NF)

Every non-key attribute is fully functionally dependent on the entire primary key. The only composite PK is BOOK_AUTHOR(BookID, AuthorID) which has no non-key attributes - 2NF is satisfied trivially.

Third Normal Form (3NF)

No transitive dependencies exist:

  • Publisher city is in PUBLISHER, not in BOOK - removing the transitive dependency Book->Publisher->City.
  • Category name is in CATEGORY, not repeated in BOOK.
  • Author country is in AUTHOR, not in BOOK_AUTHOR.
  • Fine amount is in FINE, not duplicated in MEMBER or COPY.
The schema is fully in 3NF. All determinants in non-trivial functional dependencies are superkeys of their respective tables.

08 SQL Commands (DDL & DML) with Sample Outputs

DDL - Database and Table Creation

CREATE DATABASE LibraryDBMS;
USE LibraryDBMS;

-- CATEGORY table
CREATE TABLE CATEGORY (
    CategoryID   INT PRIMARY KEY AUTO_INCREMENT,
    CategoryName VARCHAR(100) NOT NULL UNIQUE
) ENGINE=InnoDB;

-- BOOK table with FK references
CREATE TABLE BOOK (
    BookID      INT PRIMARY KEY,
    ISBN        VARCHAR(20)  NOT NULL UNIQUE,
    Title       VARCHAR(200) NOT NULL,
    CategoryID  INT NOT NULL,
    PublisherID INT NOT NULL,
    CONSTRAINT fk_book_category  FOREIGN KEY (CategoryID)
        REFERENCES CATEGORY(CategoryID) ON UPDATE CASCADE,
    CONSTRAINT fk_book_publisher FOREIGN KEY (PublisherID)
        REFERENCES PUBLISHER(PublisherID) ON UPDATE CASCADE
) ENGINE=InnoDB;

-- BOOK_AUTHOR junction table (M:N)
CREATE TABLE BOOK_AUTHOR (
    BookID   INT NOT NULL,
    AuthorID INT NOT NULL,
    PRIMARY KEY (BookID, AuthorID),
    CONSTRAINT fk_ba_book   FOREIGN KEY (BookID)
        REFERENCES BOOK(BookID)   ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT fk_ba_author FOREIGN KEY (AuthorID)
        REFERENCES AUTHOR(AuthorID) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB;

-- ISSUE table
CREATE TABLE ISSUE (
    IssueID   INT PRIMARY KEY AUTO_INCREMENT,
    MemberID  INT  NOT NULL,
    CopyID    INT  NOT NULL,
    IssueDate DATE NOT NULL,
    DueDate   DATE NOT NULL,
    CONSTRAINT fk_issue_member FOREIGN KEY (MemberID)
        REFERENCES MEMBER(MemberID) ON DELETE CASCADE,
    CONSTRAINT fk_issue_copy   FOREIGN KEY (CopyID)
        REFERENCES COPY(CopyID)   ON DELETE CASCADE
) ENGINE=InnoDB;

Books View (deduplicating author names)

CREATE OR REPLACE VIEW Books AS
SELECT
    b.BookID AS Book_ID,  b.Title,
    IFNULL(GROUP_CONCAT(DISTINCT a.Name SEPARATOR ', '), 'Unknown') AS Author,
    c.CategoryName AS Category,
    COUNT(DISTINCT CASE WHEN cp.Status = 'Available' THEN cp.CopyID END) AS Available_Copies
FROM BOOK b
JOIN CATEGORY c ON b.CategoryID = c.CategoryID
LEFT JOIN BOOK_AUTHOR ba ON b.BookID = ba.BookID
LEFT JOIN AUTHOR a ON ba.AuthorID = a.AuthorID
LEFT JOIN COPY cp ON b.BookID = cp.BookID
GROUP BY b.BookID, b.Title, c.CategoryName;

import pymysql
from config import Config

def get_connection():
    return pymysql.connect(
        host        = Config.MYSQL_HOST,
        port        = Config.MYSQL_PORT,
        user        = Config.MYSQL_USER,
        password    = Config.MYSQL_PASSWORD,
        database    = Config.MYSQL_DB,
        cursorclass = pymysql.cursors.DictCursor,
        autocommit  = True
    )

def query_db(sql, args=(), one=False):
    conn = get_connection()
    try:
        with conn.cursor() as cur:
            cur.execute(sql, args)
            return cur.fetchone() if one else cur.fetchall()
    finally:
        conn.close()

Issue Book Endpoint (key snippet)

@app.route('/api/issues', methods=['POST'])
def api_issue_book():
    data      = request.json or {}
    member_id = data.get('member_id')
    copy_id   = data.get('copy_id')
    due_date  = data.get('due_date')

    # Guard: verify copy is Available
    copy = query_db(
        "SELECT Status FROM COPY WHERE CopyID=%s", (copy_id,), one=True)
    if not copy or copy['Status'] != 'Available':
        return jsonify({"success": False, "error": "Copy not available"}), 400

    issue_date = datetime.date.today().isoformat()
    modify_db(
        "INSERT INTO ISSUE (MemberID,CopyID,IssueDate,DueDate) VALUES (%s,%s,%s,%s)",
        (member_id, copy_id, issue_date, due_date)
    )
    modify_db("UPDATE COPY SET Status='Issued' WHERE CopyID=%s", (copy_id,))
    return jsonify({"success": True})

13 Conclusion & Future Enhancements

Conclusion

This project successfully demonstrates a complete, end-to-end relational database application. The Library Circulation and Digital Resource Management System was designed from first principles using Entity-Relationship modelling, normalized to 3NF across 13 tables, implemented in MySQL 9.7 with InnoDB foreign-key enforcement, and exposed via a Flask REST API connected to a responsive browser-based UI.

The system supports all required CRUD operations (Insert, Delete, View) and executes five analytical SQL queries covering the full operational scope of a university library. The role-based interface cleanly separates Admin and Student workflows.
